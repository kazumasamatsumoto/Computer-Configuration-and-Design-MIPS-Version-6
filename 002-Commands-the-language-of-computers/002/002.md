## 2.2 | コンピュータ・ハードウェアの演算

> 「コンピュータには基本的算術演算操作を行うための命令が不可欠となる。」
> Burks, Goldstine, and von Neumann, 1946

すべてのコンピュータは算術演算を行えなければならない。MIPS のアセンブリ言語では、加算を下記のように書き表す。

```
    add a, b, c
```

これは、2 つの変数の b と c を加えて、その和を a に収めることを意味する。

この表記法は固定的である。つまり、MIPS の各演算命令で行える演算は 1 つだけであり、それに必ず変数を 3 つ付記しなければならない。たとえば、4 つの変数 b と c と d と e の和を変数 a に収めたいとする。そのためには、下記の一連の命令を実行する必要がある。

```
    add a, b, c    # bとcの和がaに収められる
    add a, a, d    # 結果として、bとcとdの和がaに収められる
    add a, a, e    # 結果として、bとcとdとeの和がaに収められる
```

結局、4 つの変数の和を求めるために、加算命令を 3 回実行する必要がある。

上記のコーディング例の中の、各行の#記号の右側の語句は人に分かりやすいように付けた注釈（comment）である。コンピュータは注釈を無視する。他のプログラミング言語とは異なり、このプログラミング言語では 1 行に 1 命令しか含めることができない。もう 1 つの C 言語との相違点は、コメントの末尾が行末によって区切られることである。

加算のような演算に必要なオペランド（operand）は、自明かもしれないが 3 つある。具体的には、加算対象の 2 つの数と和を収める変数である。すべての命令が必要とするオペランドの数を必ず 3 つにすれば、ハードウェアの単純性を保つという理念にかなう。オペランド数が可変なハードウェアは、オペランド数が固定のハードウェアよりも複雑になる。このことから、ハードウェアの設計に関する 3 つの基本原則の最初の 1 つが導き出される。

設計原則 1：単純性は規則性につながる。

上記の原始的な命令と C プログラミング言語で記述したプログラムとの関係を、以下に例題で示す。

C の 2 つの代入文の MIPS へのコンパイル
【例 題】

5 つの変数、a, b, c, d, e を含む C 言語のステートメント（statement, 文）を下に示す。Java は C 言語から進化し

はい、以下に続きを文字起こしいたします。

たものなので、この例題およびその後のいくつかの例題はどちらの高水準言語にも当てはまる。

```
    a = b + c;
    d = a - e;
```

C から MIPS アセンブリ言語への翻訳はコンパイラ（compiler）によって行われる。C コンパイラによって生成される MIPS のコードを示せ。

【解 答】
MIPS の命令は 2 つのソース・オペランドを対象に演算を行って、結果をデスティネーション・オペランドに入れる。したがって、上記の 2 つの簡単な C のステートメントをコンパイルすると、直接対応する下記の 2 つの MIPS アセンブリ言語の命令が得られる。

```
    add a, b, c
    sub d, a, e
```

C の複雑な代入文の MIPS へのコンパイル
【例 題】
5 つの変数、f, g, h, i, j を含む、先の例よりもう少し複雑な C 言語のステートメントを下に示す。

```
    f = (g + h) - (i + j);
```

このステートメントは C コンパイラによってどのように翻訳されるか。

【解 答】
コンパイラはこの C のステートメントをいくつかのアセンブリ言語の命令に分割しなければならない。なぜならば、MIPS アセンブリ言語では演算は 1 つしか行えないからである。最初の命令では、g と h の和を求める。その結果をどこかに蓄えておかなければならない。そこで、コンパイラは t0 という一時的な変数を生成する。

```
    add t0, g, h    # 一時変数t0にg+hを記憶
```

C ステートメント中の次の演算は減算である。しかし、その前に、i と j の和を求める必要がある。そこで、2 番目の命令では、i と j の和をやはりコンパイラによって生成される t1 という一時的な変数に蓄える。

```
    add t1, i, j    # 一時変数t1にi+jを記憶
```

最後に、減算命令によって、最初の和から 2 番目の和が引かれて、結果が変数 f に収められる。これでコンパイル後のコードがすべて出揃った。

```
    sub f, t0, t1    # fにt0-t1、つまり(g+h)-(i+j)を収める
```

【自己診断】
関数を記述する際に、どのプログラミング言語が最もステップ数が多くなるだろうか。下記の 3 つの言語をその順番に並べよ。

1. Java

2. C

3. MIPS アセンブリ言語

（解答）

補足：　移植性を高めるために、Java は当初はソフトウェア・インタープリタを使うように構築されていた。そのインタープリタの命令セットを Java バイトコードと呼ぶ（図 2.15 節を参照）。これは MIPS 命令セットとは大きく異なっている。同等の C プログラムに近い性能を出すために、今日の Java システムでは通常、Java バイトコードを MIPS のようなネイティブの命令セットにコンパイルする。このコンパイルは通常は C プログラムよりもずっと遅い時点で行われる。そのような Java コンパイラは、ジャストインタイム（JIT）コンパイラと呼ばれることが多い。起動プロセスにおいて、C コンパイラよりも遅い時点で、JIT がどのように使用されるかを 2.12 節で示す。また、Java プログラムをコンパイルした場合とインタープリタ方式をとる場合の性能の比較を 2.13 節で示す。

この問題について、ステップ数が多い順（最もステップ数が多い言語から少ない言語への順）に並べると：

MIPS アセンブリ言語 > C > Java

理由：

1. MIPS アセンブリ言語は最も低レベルな言語で、1 つの演算につき 1 つの命令が必要です。先ほどの例でも見たように、単純な演算でも複数のステップに分解する必要があります。

2. C 言語は中間レベルの言語で、複雑な演算を 1 行で書くことができますが、それでもある程度の明示的な手順が必要です。

3. Java は高レベルの言語で、多くの処理を抽象化できます。組み込みのメソッドやライブラリを使用することで、少ないステップ数で同じ機能を実現できます。

したがって、同じ機能を実装する場合、MIPS アセンブリ言語が最も多くのステップを必要とし、次いで C 言語、そして Java が最も少ないステップ数で実装できます。
