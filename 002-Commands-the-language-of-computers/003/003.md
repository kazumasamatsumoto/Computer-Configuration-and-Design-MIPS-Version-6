## 2.3 | コンピュータ・ハードウェアのオペランド

高水準言語で記述したプログラムとは異なり、算術命令のオペランドには制約がある。算術命令のオペランドは、ハードウェアに直接組み込まれている特殊な記憶領域の中から選んで使用しなければならない。その領域をレジスタ（register）と呼ぶ。レジスタ数には限りがある。レジスタはハードウェアを構成する基本要素であり、プログラマ側からも見える。MIPS アーキテクチャにおいては、レジスタ長は 32 ビットである。32 ビットを一まとめにしたものは頻繁に使用されるので、MIPS アーキテクチャではそれを 1 つの単位として語（word）と呼んでいる。

プログラミング言語の変数とレジスタの間の違いの 1 つに、レジスタの数は限られている点が挙げられる。一般に、MIPS のような現在のコンピュータに備えられているレジスタの数は 32 である（レジスタの数の変遷については、図 2.2.3 節を参照）。さて、シンボル表記を MIPS の言語へとトップダウンで順を追って発展させるにあたり、本節は制限を加える。それは、MIPS の算術演算命令の 3 つのオペランドにはそれぞれ、32 本ある 32 ビット・レジスタのどれかを当てなければならないということである。

このようにレジスタ数に限りがある理由は、ハードウェア設計に関する 4 つの基本原則の 2 つ目の項目に由来する。

設計原則 2：小さければ小さいほど高速になる。

「小さければ小さいほど高速である」という指針は絶対的なものではない。レジスタ数が 31 本の場合が 32 本の場合よりも速いとは限らない。しかし、この原則は観測に基づく真理であり、コンピュータの設計者はそれに真剣に対処しなければならない。プログラマはレジスタ数が多いことを望むが、コンピュータの設計者はクロック・サイクルの速度を高速に保つこととのバランスをとらなければならない。レジスタを 32 本より多く使用しないもう 1 つの理由は、命令形式中のビット数である。それについては 2.5 節で具体的に示す。

第 4 章において、ハードウェアを構築しながらレジスタが果たす中心的な役割について説明する。本章でこれから見ていくとおり、レジスタの効果的な使用はプログラム性能を改善する鍵である。

レジスタの番号を 0 から 31 の数値だけで書き表すことは可能である。しかし、MIPS の表記法では、レジスタを表すのに$記号の後ろに2文字を付けた名前を使用する。このようにした理由は2.8節で説明する。とりあえず、CおよびJavaのプログラム中の変数に対応するレジスタには$s0、$s1、...を使用し、プログラムをMIPSの命令にコンパイルするために必要な一時レジスタには$t0、$t1、...を使用することにしよう。

レジスタを使用した C の代入文のコンパイル

【例題】
プログラムでの変数をレジスタに割付けるのは、コンパイラの仕事である。先の例題のステートメントを再び取り上げよう。

```
f = ( g + h ) - ( i + j ) ;
```

変数の f、g、h、i、j をそれぞれレジスタの$s0、$s1、$s2、$s3、$s4 に割付けるとする。上記のステートメントをコンパイルした結果の MIPS アプリケーション・コードはどうなるか。

【解 答】
コンパイル結果は次のようになる。

```
add $t0, $s1, $s2 # g+hの結果をレジスタ$t0に代入
add $t1, $s3, $s4 # i+jの結果をレジスタ$t1に代入
sub $s0, $t0, $t1 # $t0-$t1つまり(g+h)-(i+j)をfに代入
```

コンパイルされたプログラムは前の例題とよく似ている。ただし、変数を L で示したレジスタ名に置き換えたことと、2 つの一時レジスタ$t0と$t1 を付け加えたことが異なる。この一時レジスタは前の例題の一時変数に相当する。

### メモリのオペランド

上の例では、変数は単一のデータ要素を表すという、単純なものである。これに対し、変数が配列や構造体というもっと複雑な形を取ることもある。配列に含まれるデータ要素の数がレジスタの数を超えることがある。そのような場合、どのようにデータを表し、どのようにそれにアクセスしたらよいであろうか。

第 1 章で最初に紹介し、本章の冒ページにも図示した、コンピュータの 5 つの構成要素を思い出してほしい。プロセッサがレジスタに格納できるデータの量はわずかであるが、メモリには膨大な量のデータを記憶できる。したがって、配列や構造体のようなデータ構造はメモリ中に保持することになる。

上で説明したように、MIPS マシンでは算術演算は必ずレジスタを用いて行われる。したがって、MIPS マシンにはメモリとレジスタの間でデータを転送する命令が備わっていなければならない。そのような命令をデータ転送命令（data transfer instruction）と呼ぶ。メモリ内の語にアクセスするためには、命令中でメモリのアドレス（address）を指定しなければならない。メモリは言わば巨大な 1 次元の配列であり、アドレスは配列のインデックスの働きをする。アドレスは 0 番から始まる。たとえば、図 2.2 において、3 番目のデータ要素のアドレスは 2 であり、メモリ[2]の値は 10 である。

メモリからレジスタへデータを転送するデータ転送命令を一般にロード（load）命令と呼ぶ。ロード命令の記述形式は、命令操作（operation）の名前、データをロードする先のレジスタ、メモリにアクセスするために使用する定数とレジスタの順である。メモリ・アドレスは命令の定数部分と 2 番目のレジスタの内容の和によって得られる。MIPS ではこの命令を lw（load word の意）と呼ぶ。

### オペランドがメモリ中にあるときの代入文のコンパイル

【例 題】
100 語から成る配列 A があるとする。また、コンパイラは変数 g と h にそれぞれレジスタ$s1と$s2 を割付けたとする。さらに配列の開始アドレスすなわちベース・アドレス（base address）はレジスタ$s3 中に収められているとする。このとき、下記の C のステートメントをコンパイルせよ。

```
g = h + A[8]
```

【解 答】
この代入文には演算が 1 つしか含まれていない。しかし、オペランドの 1 つがメモリ中にある。したがって、まず最初に A[8]をレジスタに転送しなければならない。この配列要素のアドレスは、レジスタ$s3 中の配列 A のベースと、8 番目の要素を表す数値との和である。データは、次の命令での使用に備えて、一時レジスタに収めなければならない。したがって、コンパイルされた最初の命令は下記のようになる。

```
lw $t0, 8($s3)    # A[8]が一時レジスタ$t0に代入される
```

（ここではこの命令を単純化している。後で、それを少し変更する）。A[8]の値がレジスタ$t0に入ったので、次の命令では$t0 中の値を対象にして演算を行うことができる。h($s2)をA[8]($t0)に加えて、和を g($s1)に収める。

```
add $s1, $s2, $t0 # g = h + A[8]
```

データ転送命令中の定数（8）をオフセット（offset）と呼び、アドレスを得るために加えるレジスタ（$s3）をベース・レジスタ（base register）と呼ぶ。

### 【ハードウェアとソフトウェアのインタフェース】

変数のレジスタへの割付けに加え、配列および構造体のようなデータ構造をメモリ中のロケーションに割付けることも、コンパイラの仕事である。その後で、コンパイラはデータ転送命令に配列の適切な開始アドレスを渡す。

多くのプログラムにおいて 8 ビットのバイト（byte）が有用な役割を果たすので、事実上今日のすべてのアーキテクチャでは個々のバイト単位でアドレスを表すようにしている。したがって、語アドレスはその 4 バイト中の第 1 バイトのアドレスと等しい。そうすると、順番に並んでいる語アドレスは 4 刻みで進むことになる。図 2.2 に示した概念的アドレスを実際のアドレスで表現したものを図 2.3 に示す。3 番目の語のバイト・アドレスは 8 である。

MIPS では、語アドレスは 4 の倍数でなければならない。この要件を整列化制約（alignment restriction）と呼ぶ。この要件は多くのアーキテクチャに取り入れられている（整列化すると転送速度が速くなる理由を第 4 章に示す）。

語のアドレスの付け方には、左端すなわち「ビッグ・エンド」のバイトを使用するものと、右端すなわち「リトル・エンド」のバイトを使用するものの、2 通りがある。MIPS は前者のビッグ・エンディアン（big-endian）派に属する。順序が問題になるのは、語としても 4 バイトとしてもまったく同じデータにアクセスするときだけであるので、どちらの方式であるかを意識する必要はほとんどない（付録 A に、語内のバイトに付番する 2 通りの方式を示す）。

バイト単位のアドレス付け方法は、インデックスからの配列要素のアドレス算出にも影響を及ぼす。先の例題において、正しいバイト・アドレスを得るためには、オフセットとしてレジスタ$s3 には 4×8 の値つまり 32 を収めなければならない。そうしないと、ロード元のアドレスは A[8]ではなく、A[8/4]となってしまう（2.21 節の関連する「落とし穴」を参照）。

ロードと逆の命令を一般にストア（store）と呼ぶ。つまり、ストア命令はレジスタからメモリへデータを転送する。ストア命令の形式はロード命令と似ている。具体的には、命令操作の名前、データをストアする元のレジスタ、配列要素を選択するためのオフセット、ベース・レジスタの順である。この場合も、MIPS でのアドレスは一部は定数によって、一部はレジスタによって指定される。MIPS ではこの命令を sw（store word の意）と呼ぶ。

### 【ハードウェアとソフトウェアのインタフェース】

ロードおよびストアのアドレスは、2 進数である。そのため、メイン・メモリ用の DRAM のサイズは、10 進数ではなく、2 進数で表される。つまり、ギガバイト（10⁹）またはテラバイト（10¹²）ではなく、ギビバイト（2³⁰）またはテビバイト（2⁴⁰）で示される。図 1.1 を参照。

### ロードとストアが使用されているコードのコンパイル

【例 題】
変数 h がレジスタ$s2に割付けられているとする。また、配列Aのベース・アドレスがレジスタ$s3 に収められているものとする。下記の C のステートメントをコンパイルした結果のアセンブリ・コードはどうなるか。

```
A[12] = h + A[8] ;
```

【解 答】
この C の代入文には演算が 1 つしか含まれていない。しかし、今度はオペランドの 2 つがメモリ中にある。したがって、MIPS の命令がもう 1 つ必要となる。最初の 2 つの命令は基本的には前の例題と同じである。今回の違いは、ロード命令中で A[8]を指定するためにバイト・アドレス方式に合うような適切なオフセット 32 を使用することと、加算命令の結果の和を$t0 に収めることである。

```
lw $t0, 32($s3)   # A[8]が一時レジスタ$t0に代入される
add $t0, $s2, $t0 # h + A[8]が一時レジスタ$t0に代入される
sw $t0, 48($s3)   # h + A[8]がA[12]に収められる
```

最後の命令では、オフセットに 48（4×12）を使用し、ベース・レジスタに$s3 を使用して、和を A[12]に収める。

load word と store word は、MIPS における、メモリとレジスタの間で語をコピーする命令である。別種のコンピュータでは、データを転送するために、ロードとストアの他に別の命令を使用するものがある。そのようなアーキテクチャの例として、Intel x86 を 2.19 節で取り上げる。

### 【ハードウェアとソフトウェアのインタフェース】

たいていのプログラムでは、コンピュータに備わっているレジスタの数よりも多くの変数が使用される。したがって、コンパイラは頻繁に使用される変数をレジスタに保持しておき、それ以外の変数をメモリ上に置こうとする。そのために、ロード命令とストア命令を使用して、レジスタとメモリとの間で変数をやりとりする。このように、使用頻度の低い変数、または後で必要となる変数をメモリ上に置くことをレジスタをスピル・アウト（spilling）すると言う。

レジスタはメモリよりも小さい。したがって、サイズと速度に関するハードウェアの原理から、メモリ・アクセスにはレジスタ・アクセスよりも時間がかかるのではと推測される。まさにそのとおり、データをメモリ中ではなくレジスタ中に置いた方が、アクセス速度は速い。

さらに、レジスタ中にデータがあった方が有用性が高まる。MIPS の演算命令は 2 つのレジスタを読んで、その内容に基づいて演算を行い、結果を書き込む。MIPS のデータ転送命令は 1 つのオペランドを読み出すか、1 つのオペランドを書き込むだけである。

このように、MIPS のレジスタには、アクセスに要する時間が短いと同時にメモリよりもスループットが高いという、得がたい特性がある。したがって、レジスタ中のデータは高速にアクセスできるだけではなく、容易に操作できる。また、レジスタにアクセスする方がメモリにアクセスするよりも、エネルギーの消費が少なくて済む。最高の性能を発揮させるには、命令セット・アーキテクチャは十分な数のレジスタを備えており、コンパイラはレジスタを効率よく使用しなければならない。

### 定数または即値のオペランド

プログラムにおいては、命令操作に定数を使用することが多い。たとえば、配列内の次の要素を指定するために、インデックスを繰り上げる場合がそうである。実際、SPEC CPU2017 ベンチマークを実行する際に、MIPS 演算命令の半分以上でオペランドに定数が使用されている。

ここまでに見てきた命令だけを使用するならば、定数を使用するにはそれをメモリからロードしなければならない（プログラムがロードされたときに、定数はメモリに収められているものとする）。たとえば、レジスタ$s3 に定数 4 を加えるコードは下記のようになる。

```
lw $t0, AddrConstant4($s1) # $t0 = 定数4
add $s3, $s3, $t0         # $s3 = $s3 + $t0 ($t0==4)
```

ここで、$s1+AddrConstant4 が定数 4 のメモリ・アドレスとなる。

このロード命令を使用せずに済ませる代案として、オペランドの 1 つを定数とする算術演算命令の変形版を用意する方法がある。オペランドの 1 つを定数としたこの迅速な算術演算命令を、即値加算または addi と呼ぶ。この命令を使用すれば、レジスタ$s3 に 4 を加算するには、下記のように記述するだけで済む。

```
addi $s3, $s3, 4          # $s3 = $s3 + 4
```

オペランドが定数であるケースは頻繁に発生する。したがって、定数を算術演算命令内に含めれば、定数をいちいちメモリからロードするよりも、処理がはるかに高速になり、使用するエネルギーが少なくて済む。

定数を含めることの妥当性を判断するのに頻度を使用することは、主要なアイデアの「一般的な場合を高速化する」のもう 1 つの例である。

【自己診断】
レジスタが重要なのは分かったが、チップ内のレジスタの数は年月の経過とともにどのような割合で増加するか。

1. 非常に早く増加：レジスタの数は Moore の法則に従って増加する。つまり、24 か月ごとに数が倍増する。

2. 非常にゆっくり増加：プログラムは通常はコンピュータの言語の形で配布される。命令セット・アーキテクチャには慣性がある。したがって、レジスタの数は新しい命令セットが登場する度に増える程度である。

（解答）

この自己診断問題の正解は、2 番の「非常にゆっくり増加」です。

その理由は以下の通りです：

1. 命令セット・アーキテクチャ（ISA）の後方互換性が重要です。既存のプログラムを新しいプロセッサでも実行できるようにするため、レジスタの基本的な構成を大きく変更することは難しいのです。

2. プログラムはコンピュータ言語の形式で配布されるため、そのプログラムがコンパイルされる際に利用できるレジスタの数は、その命令セットが定義する数に制限されます。

3. アーキテクチャの慣性（変更への抵抗）が大きく、いったん確立された命令セットの基本構造を変更するのはコストと互換性の面で困難です。

4. Moore の法則はトランジスタの集積度に関する法則であり、確かにチップの性能は向上しますが、それはレジスタの数の増加には直接結びつきません。

したがって、レジスタの数の増加は、新しい命令セットアーキテクチャが登場する際にのみ、段階的に行われる程度に留まります。これは、ソフトウェアの互換性と実用性を維持するための重要な設計上の判断と言えます。

補足： 本書で取り上げる MIPS レジスタのデータ長は 32 ビットであるが、64 ビット版の MIPS 命令セットもある。後者は 64 ビットのレジスタを 32 本備えている。両者を区別するために、正式には MIPS-32 および MIPS-64 と呼ぶ。本書では MIPS-32 のサブセットを使用する。図付録 E に、MIPS-32 と MIPS-64 の違いを示す。2.16 節および 2.17 節に、32 ビットのアドレスを用いた ARMv7 と、その後継である 64 ビット・アドレスの ARMv8 との、さらに大きな違いを示す。

補足： ベース・レジスタにオフセットを加えてアドレスを決定する MIPS の方式は、配列および構造体ともきわめてよく適合する。レジスタで配列および構造体の始点を指し、オフセットで欲しい要素を選択できるからである。その例を 2.13 節で見ることにする。

補足： データ転送命令中のレジスタは元来は配列のインデックスを保持するために考案され、オフセットは配列の開始アドレスを指すために用いられた。そのような訳で、ベース・レジスタはインデックス・レジスタ（index register）とも呼ばれる。今日では、メモリははるかに大きくなり、データの割当てに関するソフトウェア・モデルもはるかに精巧になっている。そのため、配列のベース・アドレスは通常はレジスタに渡される。オフセットには収まりきらないからである。この点については、後で見ることにする。

補足： MIPS では負の定数を使用できるので、即値減算命令は必要がない。
