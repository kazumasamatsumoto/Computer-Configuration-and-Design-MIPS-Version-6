## 1.11 誤信と落とし穴

> 「科学は神話および神話に対する批判から始まる。」
> Sir Karl Popper*, The Philosophy of Science, 1957
> *（訳注）カール・ポッパー卿、 英国の哲学者、1902 -

各章には「誤信と落とし穴」という節を置く。目的は、一般に流布している誤解を解くことである。そのような誤解を本書では「誤信」と呼ぶことにする。誤信について説明する際には、反証となる例を示すように努める。また、「落とし穴」つまり犯しやすい誤りも取り上げる。落とし穴に陥る原因の多くは、一定の状況のもとで成立する原理を一般化してしまうことにある。この節を読めば、読者がコンピュータを設計または使用する際に犯しやすい誤りを回避できるだろう。著者自身も含めて、コンピュータ設計者の多くは、コスト性能比に関して誤信にとらわれたり落とし穴に陥ったりしている。したがって、例を挙げるには事欠かない。最初に示す落とし穴は多くの設計者が陥ったことのあるもので、コンピュータの設計要素間の重要な関係を示している。

落とし穴： コンピュータのある面を改善することによって、その改善度に等しい性能向上を期待すること。

一般的な場合を高速化するという素晴らしいアイデアから思わしい結果が得られないことに、ハードウェアおよびソフトウェアの両方の設計者が悩まされてきた。そのことは、改善の度合いは該当の事象が占める割合に左右される、ということを思い出させる。

簡単な例で説明しよう。あるコンピュータ上で実行に 100 秒かかるプログラムがあり、そのうちの 80 秒が乗算によって占められているとする。このプログラムの実行速度を 5 倍速くしたければ、乗算の速度をどのくらい改善しなければならないだろうか。

改善を行った後のプログラムの実行時間は下記の式によって表される。この式を Amdahl の法則（Amdahl's law）と呼ぶ。

```math
実行時間_{改善後} = \frac{実行時間_{改善の影響を受ける}}{改善度} + 実行時間_{改善の影響を受けない}
```

この式に上の問題を当てはめると、下記のようになる。

```math
実行時間_{改善後} = \frac{80}{n} + (100 - 80)
```

性能を 5 倍改善するためには、改善後の実行時間は 20 秒にならなければならない。したがって、上の式は下記のようになる。

```math
20秒 = \frac{80秒}{n} + 20秒
```

```math
0 = \frac{80秒}{n}
```

この結果は、乗算をいくら速くしても、乗算の占める割合が 80%しかない場合、全体の性能を 5 倍改善することはできないことを意味する。ある面を改善したことによる性能の向上は、その改善された機能が使用される割合に制約されるのである。この概念を経済学では収穫逓減の法則と呼んでいる。

ある新機能に費やされる時間とその新機能がもたらす潜在的な速度向上率がわかっていれば、Amdahl の法則を適用して実際にどれくらいの性能改善が得られるかを予測できる。Amdahl の法則を CPU 性能の方程式と組み合わせて用いれば、機能改善を行った場合の結果を評価できる便利なツールとなる。Amdahl の法則については、演習問題でさらに詳しく検討する。

Amdahl の法則は、並列プロセッサの数の現実的な上限に関する議論にも使用される。この議論については、第 6 章の「誤信と落とし穴」の節で検討する。

誤信： コンピュータの利用率が低ければ、消費電力は少ない。

サーバーの負荷は時間変動するので、利用率が低いときの電力効率は重要である。たとえば、Google のウエアハウス・スケール・コンピュータのサーバーの CPU 利用率は、10%～ 50%の間に収まっている時間帯がほとんどで、100%に達するのは全時間の 1%弱である。5 年間にわたって SPECpower ベンチマーク・テストを効果的に行う方法を学んだ後でも、2020 年において、最善の結果が得られるように特別に構成したコンピュータをもってしても、負荷が 10%のときに、依然としてピーク電力の 33%を使用している。SPECpower ベンチマーク・テスト向きに構成されていない一般のシステムでは、結果はさらに悪い。

サーバーの負荷の変動にかかわらず、電力の消費がピーク時の値に比べ大きな割合を占めていることから Barroso と Urs Hölzle は、「エネルギーに比例してコンピュータを利用できるように」ハードウェアを設計し直すべきであるという議論を提起している[Barroso and Urs Hölzle, 2007]。たとえば、将来のサーバーが、負荷が 10%のときにはピーク時の電力の 10%しか使用しないならば、データセンターの電気代を節約することになり、炭酸ガス排出について関心が高まっているこの時代において、優良企業となるだろう。

誤信：性能を上げる設計とエネルギー効率を上げる設計とは、目標的に無関係である。

エネルギーは電力と時間の積である。したがって、時間を短縮するようにハードウェアまたはソフトウェアを最適化すると、エネルギーも全般的に節減されることが多い。たとえ、その結果として、エネルギーの使用量が少し増えたとしてもである。その 1 つの理由は、該当のプログラムが実行されているときに、そのコンピュータの他のすべての部分でもエネルギーを消費しているので、最適化された部分では少し多くエネルギーを消費したとしても、その時間が短縮されればシステム全体のエネルギー消費が節減されよう。

落とし穴：性能の尺度に性能方程式の一部を使用すること。

クロック周波数、命令数、CPI のどれか 1 つだけに基づいて性能を予測する、という危険についてすでに警告した。もう 1 つの一般的な誤りに、この 3 つの要素のうちの 2 つだけを使用して性能を比較するというものがある。特定の状況では、3 つの要素のうちの 2 つを使用することが有効な場合もあるが、同時にそれは容易に誤解を招きかねない。実際、時間以外を速度性能の尺度として使う代案がいろいろ提案されたが、それらのほとんどは誤解を招く主張、結果の曲解、あるいは不正確な解釈を生むことにつながっている。

尺度に時間を使う代わりに MIPS（million instructions per second）値を用いる性能表現法がある。これは 1 秒当たりの命令実行数を 100 万単位で数えたものである。あるプログラムに関して、MIPS 値は下記のように表される。

```math
MIPS = \frac{実行命令数}{実行時間 \times 10^6}
```

MIPS 値は命令実行速度なので、実行時間の逆数の形で性能を表す。つまり、速いコンピュータほど MIPS 値が大きい。この点は直感的に分かりやすく、MIPS 値の長所と言える。

コンピュータ性能の比較基準として MIPS 値を使用することには、問題が 3 つある。まず、MIPS 値は命令実行速度を表しはするが、命令の働きを考慮に入れていない。したがって、MIPS 値を使用して、命令セットの異なるコンピュータを比較することはできない。命令セットの異なるコンピュータ間では実行命令数が違ってくるからである。第 2 に、同じコンピュータ上でも、プログラムが違えば MIPS 値も違ってくる。したがって、1 機種のコンピュータに MIPS 値がいくつもあることになる。たとえば、上式の中の実行時間に CPU 性能方程式を代入すると、MIPS 値とクロック周波数と CPI との関係は下記のようになる。

```math
MIPS = \frac{実行命令数}{\frac{実行命令数 \times CPI}{クロック周波数} \times 10^6} = \frac{クロック周波数}{CPI \times 10^6}
```

図 1.18 において、Intel Xeon 上で実行した SPECspeed 2017 Integer に関して、CPI の変動幅が 4 倍あった。MIPS 値も同様に変動する。最後にこれが一番重要な点だが、もし新しいプログラムがより多くの命令を実行するか命令がより高速であるならば、MIPS 値は性能とは無関係に変化するのである。

【自己診断】
あるプログラムに関して、下記の性能測定値があるとする。

![001.png](./img/001.png)

| 測定項目       | コンピュータ A | コンピュータ B |
| -------------- | -------------- | -------------- |
| 実行命令数     | 100 億         | 80 億          |
| クロック周波数 | 4GHz           | 4GHz           |
| CPI            | 1.0            | 1.1            |

a. MIPS 値はどちらのコンピュータが高いか。

b. どちらのコンピュータが高速と言えるか。

【解答】

この問題を順番に解いていきましょう。

a. MIPS 値の計算：

MIPS 値の公式は以下の通りです：

```math
MIPS = \frac{クロック周波数}{CPI \times 10^6}
```

コンピュータ A：

```math
MIPS_A = \frac{4 \times 10^9}{1.0 \times 10^6} = 4000
```

コンピュータ B：

```math
MIPS_B = \frac{4 \times 10^9}{1.1 \times 10^6} \approx 3636
```

したがって、コンピュータ A の MIPS 値の方が高い。

b. 実際の性能（実行時間）の計算：

CPU 性能の方程式：

```math
実行時間 = \frac{実行命令数 \times CPI}{クロック周波数}
```

コンピュータ A：

```math
実行時間_A = \frac{100億 \times 1.0}{4 \times 10^9} = 2.5秒
```

コンピュータ B：

```math
実行時間_B = \frac{80億 \times 1.1}{4 \times 10^9} = 2.2秒
```

したがって、実行時間が短いコンピュータ B の方が高速である。

この結果は、MIPS 値が必ずしも実際の性能（実行時間）を正確に反映しないことを示す良い例となっています。コンピュータ B は実行命令数が少ないため、CPI が若干大きく MIPS 値が低いにもかかわらず、実際の実行時間では優れた性能を示しています。

---

Amdahl の法則（<<）
ある改善を行った結果の性能の向上は、改善した機能を使用する割合によって制約される、という意味の法則。これは収穫逓減の法則の定量版である。

MIPS 値（<<）
毎秒 100 万回の命令操作の実行を 1 単位として、プログラムの実行速度を測定したもの。値を算出するには、実行された命令数を実行時間と 10⁶ の積で割る。
